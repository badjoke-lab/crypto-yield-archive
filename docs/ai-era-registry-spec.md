# CYA AI-era Registry Specification

Status: planned / mandatory future-work reference

## Goal
CYA must answer not only what yield/lending platform failed or changed, but what happened afterward to claims, recoveries, restructuring and users. Generic AI summaries are not the product; reviewed lifecycle evidence is.

## Required work
- Preserve reviewed canonical data and existing development/evidence policy.
- Extend lifecycle coverage where supported: withdrawal freeze -> insolvency/default -> bankruptcy/restructuring -> claims process -> recoveries/distributions -> final/current outcome.
- Make provenance, source quality, uncertainty and last verification visible and machine-readable.
- Add deterministic record-level JSON derived from canonical data; no separate AI source of truth.
- Strengthen filters for status, failure/cause, jurisdiction, claims state, recovery/distribution state, dates and evidence quality where schema support exists.
- Add/strengthen Compare around user-relevant lifecycle outcomes rather than advertised yield rankings.
- Add Stats for failure causes, claims/recovery coverage, outcome state, timelines and registry data quality.
- Keep automated monitoring/staging non-canonical until reviewed.

## Non-goals
No AI-generated canonical facts, investment recommendations, yield rankings, prompt buttons or public chatbot as priority work.

## Mandatory reference
Future CYA schema, record-growth, monitoring, UI, comparison, stats and machine-readable work must consult this file alongside the existing methodology/development policy. Stricter existing evidence rules win.
